## Web恢复

在仓库根目录执行。先按项目说明安装Node/Python依赖、初始化MySQL和 `.env.local`，并创建目标管理员/分析员账号。若需要同时展示武川两组，应先按仓库现有流程导入两组记录并关联武川风场/R024。

```sh
# 只读校验：所有文件SHA-256、ZIP CRC、60条完整记录及数据集数量
node node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json scripts/restore-customer-demo.ts

# 导入并重新分析；默认目标账号admin，也可传 --username=用户名
node --env-file=apps/web/.env.local node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json scripts/restore-customer-demo.ts --apply

# 核验当前检测结果
node --env-file=apps/web/.env.local node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json scripts/verify-huade-demo-detection.ts
```

恢复脚本按接收环境的账号及对象ID重新关联，不复制原环境账号。它校验并导入化德原生记录、显式登记场景批次、恢复两份风场数据、重算三片叶片并评价。已存在的相同文件/风场数据复用；有冲突则停止，不覆盖既有样本。重跑会生成新的处理/评价版本，历史保留。旧版R025展示批次若尚未迁移至020#，脚本会明确报错，应先用已有迁移流程处理，不能混合两套归属。

预期化德结果：叶片1/3各0/100项超限，叶片2有31/100项超限，触发“疑似损伤·高风险”；各叶片工况匹配20/20。算法读取当前波形特征，不能以叶片编号或生成假设代替计算。该异常预警不能确诊裂纹。

武川健康标准需要在两组各三片叶片完成分析后，另按 `docs/project-health-standard-20261110.md` 运行 `scripts/setup-project-health-standard.ts`，将标准绑定接收环境的处理版本。化德场景自带冻结参考，不依赖原环境的数据库ID才能计算。
