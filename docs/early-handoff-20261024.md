# 提前触发后的换点与单点记录分离

本次仅调整上位机；Mac、Windows 共享服务与界面，固件和运动参数不变。

| 环节 | 修改前 | 修改后 |
|---|---|---|
| 移动中识别完整进入/离开 | 记住事件 | 记住事件，算法和角度配置不变 |
| 当前运动完成 | 确认停止、核验目标/参考 | 保留确认；仍需到位、无故障 |
| 创建单点文件与索引 | 下一次换点前执行 | 任务收尾时执行 |
| 再次建立 SDK 采样边界 | 提前事件已有边界，仍重复建立 | 已有提前事件时不再建立 |
| 等首批单点数据 | 即使事件已经结束，仍需等新数据 | 不再要求额外数据包 |
| 下发下一点 | 上述步骤结束后 | 核验通过、记录连续流书签后进入运动流程 |
| 单点文件的数据 | 可能只有事件结束后的20 ms静止数据 | 从连续原始记录复制该次候选事件的真实样本 |
| 完成状态 | 实际写盘后 | 仍在实际写盘后，不以书签代替完成 |

适用于开启“测试：未停稳时判定叶片”、且在单点采集准备前已有完整提前事件的情况。没有提前事件、普通采集、正常停稳后采集均保留原流程。没有增加新的操作步骤。

快速换点仍由唯一的运动线程顺序发起，当前点的观察器先关闭，下一段运动建立独立观察器，不重复消费同一事件。取消、参考变化、信号中断、激光异常或原始流写盘错误不能被提前事件绕过。

全量原始记录持续保存。单点文件在原始记录完成落盘后按全局索引截取，保留速度、回波、量程标记以及任务/叶片/点位归属；局部文件从0重新编号，全局关联保留在 `continuousSession` 和 `diagnosticDetection` 中。文件仍标记为诊断、非有效测量，不能据此宣称移动抖动已经被消除。

未落盘的单点显示为未完成，不进入已保存计数。若文件生成失败，任务报错，原始记录和书签保留；进程意外中断也不会将未生成记录伪装成成功。这里没有增加自动恢复丢失单点文件的承诺。

## 验证方式

- Mac `.dylib` 与 Windows `.dll` 两种 SDK 生命周期测试：3个圆周点位，只在第一点开放单点窗口；后两点的完整经过仅在运动中提供，之后不提供额外数据包，仍能完成任务。
- 第三点指令下发时，第二点文件尚未创建；后续实际复制的数据逐样本与连续原始文件对比，除局部索引外完全一致。
- 停止确认之前不允许下发第三点；取消或参考异常阻断第三点；延迟复制失败必须反馈任务错误。
- 区间复制覆盖跨文件分块、稀疏 RSSI、量程标记、原始索引损坏、无效区间与取消后的保存。
- 日志保留 `detectedAt`、`stopConfirmedAt`、`observedAt`、`motionCommandAt`，并新增 `recordPreparationDeferred`、`early_handoff_ready`、`recordMaterializedAt`，用于后续实机分解耗时。

以上为离线协议/线程/真实临时文件验证。本次没有进行现场电机运动测试，不把测试桩运行速度当作真实转盘速度，也不承诺每次都能跟上5秒一圈的目标叶片。后续现场应重点比较“停止确认 → 下一条命令发送”以及“检测到离开 → 下一点到位”的耗时。

本次通过采集服务全量823项测试、Web/桌面 TypeScript 检查、自动跟随与桌面字段/桥接测试，以及桌面构建。没有生成新的 Windows 安装包；同事通过源码更新构建即可使用共享服务改动。
