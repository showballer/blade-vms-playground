# 项目叶片健康标准与检测闭环

## 判定范围

健康标准由用户于 2026-11-10 确认为健康的两批数据建立：武川风场-R024-1101-第一组、第二组，每批三片叶片，共 120 条记录。绿色“健康”表示本项目标准适用范围内的振动响应正常，不等同于已证明叶片不存在任何结构缺陷。

标准按风场和风机业务编号关联，不依赖数据库中的本机对象 ID。两批保留为两个场景，各场景分别统计 P1–P5、0°/90°/180°/270°；不会把所有测点合成一个全局阈值。不同半径、测量方向或处理配置不能混用。

源文件的历史增益修订、人工角度分组、估算测点位置和原始身份标记全部保留。用户的健康声明存入标准确认依据，未将源文件改成“仪器独立核验通过”。基线自身的检查注明“基线回代”，不用于估计独立检出准确率。

## 五项判据

每条记录的全部有效连续段分别计算，速度 RMS 和半峰峰值取段间最大值；峰值因子、普通峭度在不少于 32 样本的段上取最大值，短段不计算这两项。主响应峰频率取已保存代表段在处理方案请求频带内的最大幅值谱峰，指响应峰，不是结构固有频率。拼接接缝、模型拟合曲线不参与检测。

同一场景、同一测点/角度下三片健康叶片的指标最小值为 L，最大值为 U，中位数为 M：

| 指标 | 标准范围 |
|---|---|
| 速度 RMS、速度半峰峰值 | [max(0,L−0.10M), U+0.10M] |
| 主响应峰频率 | [max(0,L−Δ), U+Δ]，Δ=max(0.05M，基线该槽位最大频率分辨率) |
| 峰值因子、普通峭度 | [max(0,L−0.20M), U+0.20M] |

外扩比例是项目初始工程容差，不是行业损伤标准，也没有损伤样本标定。后续可依据独立健康/损伤样本重新发布标准版本，旧版本和报告保留。

## 适用性检查

- 必须保存发布整叶片分析，完整覆盖 P1–P5 四角度，五项指标有效，数据质量合格；缺项不补零。
- 新批次需在“健康标准与核验 → 核验身份与分组”确认叶片、测点和角度；已确认健康基线用标准发布时的用户声明。
- 处理算法、去趋势、滤波、窗函数、方向/几何方案、采样率须与至少一个完整基线场景一致；不得逐点挑选不同场景阈值。
- 测点半径差不得超过 max(0.5m，基线半径的2%)；当前频率分辨率不得粗于对应基线最大分辨率的2倍。通过分辨率检查后，频率比较容差至少覆盖当前一格频率分辨率。
- 风速与主轴转速须真实同期匹配，并在对应场景观测范围分别外扩 0.5m/s、0.5rpm 内。每秒区间均值用于平均工况比较，不用于瞬时转速、相位或阶次；未知语义、时间平移测试副本、冲突工况不能用于评价。
- 配置、位置或工况不适用时显示“待复核”，不能直接判损伤。

## 检测与发布

1. 导入新批次，关联同一风场和风机，导入同期风场数据集并选择关联。
2. 完成叶片响应分析并保存版本，可在健康监测直接启动整叶片分析。
3. 完成身份及分组核验，点击“重新关联工况与更新评价”。
4. 在适用场景内，100项指标均在范围内显示“健康”。任一项超限显示“疑似损伤”：单记录单指标为中风险；同一记录至少两项超限或至少两条记录超限为高风险。界面列出测点、角度、本次值、允许范围。
5. 通过“复核并发布结论”记录复核说明、检测/巡检报告编号或其他依据、人员和时间。超限版本可发布“损伤”或“待复核”；有超限不能直接覆盖成健康。健康版本可发布健康；没有超限不能从本流程直接发布损伤。
6. 损伤结论绑定处理版本、标准版本、身份核验和工况修订。任一依赖变化需重新评价并复核；历史记录保留。
7. 新生成的报告预览及 Word 报告包含相同结论、标准、基线回代/独立筛查标记、超限明细、复核依据。旧报告是不可变快照，不自动改写。

该算法已接入自动异常筛查，不是裂纹/腐蚀类型识别器。尚未导入真实损伤样本，因此不能承诺检出率、误报率或“任何损伤都能检出”；后续损伤数据可能落在当前宽范围内，届时需据真实对照修订特征或模型，不能为得到标签强行调整原始数值。

## 开发环境恢复

在导入仓库两组原始数据、确认风场数据关联、完成六片整叶片分析后运行：

```sh
node --env-file=apps/web/.env.local node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json scripts/setup-project-health-standard.ts
node --env-file=apps/web/.env.local node_modules/tsx/dist/cli.mjs --tsconfig apps/web/tsconfig.json scripts/setup-project-health-standard.ts --apply
```

默认已有 admin，也可使用 `--username=分析员用户名`。脚本默认预览，显式 apply 才发布六个分析版本、建立用户已确认健康标准和保存评价；不创建账号、不复制凭据、不修改原始波形。页面“健康标准”可为新样本发布后续版本。

验证：

```sh
npm run typecheck
node_modules/.bin/tsx scripts/test-project-health-standard.ts
node_modules/.bin/tsx --tsconfig apps/web/tsconfig.json scripts/test-project-health-review.ts
node_modules/.bin/tsx scripts/test-health-report-model.ts
node_modules/.bin/tsx --tsconfig apps/web/tsconfig.json scripts/test-health-injection-rollback.ts
npm run build -w @blade/web
```
