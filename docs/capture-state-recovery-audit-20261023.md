# 采集按钮与异常恢复检查（2026-10-23）

本次检查覆盖普通采集、手动点位联动、自动跟随、预定位、停止保存、公共原点、转盘状态与恢复、服务重启。Mac 和 Windows 使用同一套界面与 IPC；平台启动差异另用 Python 模块／Windows EXE 的进程替身验证。没有连接真实设备，没有修改固件或用户采集数据。

## 修复与保留的条件

| 场景 | 处理 | 仍需满足的条件 |
| --- | --- | --- |
| 上一次点位停留在“换点中”等历史阶段 | 空闲／异常且接收线程退出后，历史阶段不再锁定配置、归零 | 当前采集、保存、设备操作和转盘任务仍阻止冲突操作 |
| 联动采集结束后切回普通采集 | 新普通任务清除当前状态中的旧点位信息，历史记录保留 | 旧接收线程和异步写盘必须已经收尾 |
| 回原点异常、停止无法确认 | 释放界面全局占用，允许进入转盘状态检查、清故障或重试停止 | 未核实前不允许重新回原点；新反馈确认停止后才解除本项等待 |
| 回原点等待期间服务代际／连接改变 | 取消旧界面等待，保留原点坐标，不恢复旧运动 | 新连接重新读取并匹配硬件参考位 |
| 缓存显示轨迹运行／故障 | 明确点击开始时只做一次重新读取；不重复使用旧异常判断 | 新读回仍运行／故障则拒绝发出开始命令 |
| 停止失败、后台仍显示 stopping | 停止按钮可原地重试 | 本次停止请求尚未结束时禁止重复点击；新采集仍被占用状态拦截 |
| 读取状态失败，但服务进程仍存在 | 保留最后已知运行占用及停止入口，标明读取失败 | 不把通信失败当作采集已停；新读回后更新状态 |
| 服务进程确认退出／强制关闭后 | 清除该进程的旧 busy 标记，并取消其未完成 HTTP 请求 | 不把它当作硬件停稳或数据完整保存；新服务须重新核验 |
| 回原点任务被替换／丢失或过期 | 退出等待并请求停止，不无限轮询 | 不把不同目标的返回值当作本次到位结果 |

启动失败、预定位失败均释放本次界面占用。预定位成功后开始采集，不重复下发同一首点移动。启动回包未返回时可请求停止；IPC 保持开始与停止的次序，晚到的开始回包不能恢复已取消的界面任务。

## 回归入口

- `npm run test:field`：采集界面契约、服务桥接、原点、预定位、状态恢复等。
- `npm run test:auto-follow`：手动／自动路线配置、逐点采集、汇总和按钮状态。
- `npm run test:field-recovery`：隔离用户目录、临时账号、内存服务和真实 Electron IPC 的界面流程；禁止访问外网和设备。
- `node --test scripts/test-windows-packaged-bridge.cjs scripts/test-field-capture-main.cjs scripts/test-field-capture-tracker.cjs`：打包模块依赖、主进程与保存／上传跟踪。
- `PYTHONPATH=services/acquisition services/acquisition/.venv/bin/python -m unittest discover -s services/acquisition/tests`：采集服务完整回归。

新增隔离流程结果写入 `artifacts/capture-state-audit-20261023/results.json`，包含八项场景及实际请求顺序。其他原有界面回归覆盖手动配置、状态检查、故障恢复、记录预览与导出入口。

验证范围是本地软件与接口回归。Windows 实机、真实电机运动、激光采集、可靠上传需要对应运行环境验收；本次不把进程替身或内存接口测试记作实机通过。Windows 发布时应同时重新构建采集服务与桌面客户端，不能只替换前端文件。
